Guidance for AI coding agents (Claude Code, Copilot, Cursor, Codex, ...) working on this repository.

## Project

Motorcycle on-board computer that replaces the analog gauge cluster of a Zanella RX 150. It reads
wheel speed, engine RPM, fuel level and GPS position and shows them on two 128×64 I2C OLED displays,
plus two 10-LED bar graphs driven by PWM. It was the final project for *Seminario de Sistemas
Embebidos* (FIUBA, 2020–2021) and is being revived.

- MCU: STM32F103 "Blue Pill", Cortex-M3 @ 72 MHz (8 MHz HSE × 9). Project and linker script target
  the `STM32F103CBTx` (128 KB flash / 20 KB RAM); the firmware (~24 KB) also fits a C8 (64 KB).
- Framework: STM32Cube HAL (STM32Cube FW_F1 V1.8.3), generated by STM32CubeMX with the *Makefile*
  toolchain. Bare-metal, no RTOS: `main()` calls `setup()` once and `loop()` forever (`Core/Src/app.c`).
- Hardware design: KiCad 5.1 (`Kicad/`). Schematics are empty; only the PCB layouts exist (see #15).

## Build and flash

```sh
make -j            # build/Ordenador-abordo.{elf,hex,bin,map}
make clean
make flash         # st-flash write build/Ordenador-abordo.bin 0x8000000
make erase
```

Requirements: `arm-none-eabi-gcc` + newlib, GNU make, `stlink-tools` (`st-flash`) for flashing.
On Windows, STM32CubeCLT provides the toolchain; use `GCC_PATH=...` if it is not on `PATH`.

There is no simulator or hardware-in-the-loop setup. **You cannot verify runtime behaviour**; a clean
build is the minimum bar. Say so explicitly when a change needs testing on the bike.

CI (`.github/workflows/build.yml`) builds the firmware on every push/PR, uploads the binaries, and runs
an informational `cppcheck` on `Core/`.

## Rules

1. **CubeMX-generated files**: only write between `/* USER CODE BEGIN x */` and `/* USER CODE END x */`.
   Anything outside those markers is overwritten when the `.ioc` is regenerated. Pin or peripheral
   changes go in `Ordenador-abordo.ioc` first, then regenerate; never hand-edit `MX_*_Init()`.
2. **Never modify `Drivers/`.** Upgrading the HAL is done by regenerating from CubeMX (see #17).
3. When adding a `.c` file, add it to `C_SOURCES` in the `Makefile` (CubeMX also regenerates the Makefile,
   so keep project additions near the top of the list and re-check after regenerating).
4. **ISR safety**: anything written in an interrupt/HAL callback (`HAL_GPIO_EXTI_Callback`,
   `HAL_UART_RxCpltCallback`, ...) and read in `loop()` must be `volatile`; multi-byte structs must be
   copied atomically. Keep callbacks short: set flags or copy data, do the work in `loop()`.
5. No dynamic allocation (`malloc`) and no blocking delays inside callbacks. Prefer `snprintf` with
   `sizeof` over `sprintf`.
6. Keep hardware-independent logic (parsing, unit conversions) free of HAL includes so it can be unit
   tested on the host (#16).
7. Do not commit build output, KiCad backups (`*-bak`, `_autosave-*`) or `fp-info-cache`.
8. Write in **English**: code comments, commit messages, issues, PRs and docs. (Some existing identifiers
   are in Spanish, e.g. `vueltas`, `cadena`; renaming them is fine as part of related work.)

## Hardware reference

| Pin | Function | Peripheral / config |
|---|---|---|
| PA0 | Push button | EXTI0, rising edge, pull-up |
| PA1 | LED bar graph 2 (LM3915 input) | TIM2_CH2 PWM |
| PA2 | LED bar graph 1 (LM3915 input) | TIM2_CH3 PWM |
| PA6 | Engine RPM (rectified ignition signal) | ADC1_IN6 |
| PA7 | Fuel level (tank sender divider) | ADC2_IN7 |
| PA8 | Wheel-speed switch | EXTI8, rising edge, pull-down |
| PA9 / PA10 | HC-05 Bluetooth (also debug output) | USART1 TX/RX, 9600 8N1 |
| PB8 / PB9 | OLED displays | I2C1 SCL/SDA (remapped), 400 kHz |
| PB10 / PB11 | u-blox NEO-6M GPS | USART3 TX/RX, 9600 8N1, RX via DMA1 Ch3 |
| PA13 / PA14 | SWD | SWDIO / SWCLK |

- Displays: SSD1306 0.96" at 8-bit address `0x7A` and SH1106 1.3" at `0x78`, sharing the same I2C bus.
- TIM2: prescaler 47, period 199 → 7.5 kHz PWM, duty 0–200; `pwm1[]`/`pwm2[]` map 0–10 LEDs to duty.
- Fuel sender: 100 Ω (reserve) to 8 Ω (full) to GND, with a 100 Ω pull-up to 3.3 V → ADC ≈ 100–2048.
- RPM input: diode + 100 kΩ / 100 kΩ divider + 100 nF + 5.5 V Zener clamp; the reading only grows
  monotonically with RPM, it is not calibrated.
- Timezone is hardcoded to UTC-3 (`GMT` in `gps.h`).

## Known issues

The open GitHub issues (#1–#18) describe known bugs and planned work. Check them before changing
related code, and reference them in commits/PRs (`Fixes #N`). The most important ones are the GPS
receive/parse bugs (#1–#3) and the ISR shared-state problem (#4).
